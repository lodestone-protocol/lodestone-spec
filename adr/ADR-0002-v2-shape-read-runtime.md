# ADR-0002: Lodestone v2.0——知识的形状 + 读取的方法 + 运行的时（Draft）

> **状态**: Proposed（等待 Jasonmilk 评审后转 Accepted）
> **日期**: 2026-09-06
> **范围**: lodestone-spec 协议级决策（v2.0 换代）
> **关联**: v1.3.0（冻结不迁移）、Helix VISION（按需加载/按需驱动/极致节能/确定性优先）、ADR-0022（会话即经历，Helix-Mind）

---

## 背景

v1.3 以 HTML 注释 `<!-- mddag: {...} -->` 承载 JSON 元数据，把 DAG 结构
隐式藏在注释里。三个问题（评审结论，2026-09-06）：

1. **载体多余**：markdown 大纲（heading 层级）本身就是骨架——树/森林/
   跨树引用天然构成 DAG。HTML 注释是自造的隐身平行结构，一张图撕两半，
   需专用解析器提取 L1，25 Golden Fixtures + 14 诊断码都在养这个中间层。
2. **骨架也会膨胀**：v1.3 只有"读取分三级"（L1/L2/L3），没有"读取
   方法论"——长会话后期 L1 骨架本身失控，给 AI 读什么、按什么粒度，
   未定义。
3. **没有运行时**：v1.3 是文档格式，不是会话协议——对话中"AI 说话自动
   DAG 化、按需获取"的摄取语义未定义。

**核心立场（Jasonmilk，2026-09-06）**：DAG 是知识的形状，读取是方法的
问题，归位是运行时的事。v2.0 把三者合一：**大纲即骨架、链接即磁力线、
正文即铁粉、状态是列表；收敛即压缩、读取按需下钻、追加流式归位。**

## 决策

| 决策 | 内容 |
|---|---|
| **D1 形状** | 载体从 HTML 注释 JSON 换成 **markdown 原生结构**：根级 `#` 标题 = 球（节点）；子标题层级 = 球内结构（树）；正文段落 = 铁粉（吸附的信息）；跨树引用 = markdown 链接 `[标签](#slug)`（磁力线）；状态 = 正文顶部元数据列表 `- status: draft\|converged\|aligned`。零 HTML 注释、零 JSON。 |
| **D2 id** | 纯 slug 派生（复用 v1.3 §4.2 算法），消灭显式 `id` 声明。E-DUP-ID 语义保留。 |
| **D3 边** | 只有指向**根级标题 slug** 的链接算磁力线边（生效语义保留：双端 aligned 才生效）；链接文本 = 关系标签（自由文本，不设固定枚举——语义由状态机语境解读，协议只保证"边存在 + 目标合法"）。指向子标题的链接是普通 markdown 链接，协议不管。 |
| **D4 状态** | `- status:` 列表项，位置 = 标题后第一个非空块。状态机 draft → converged → aligned 保留；非法转移报错。 |
| **D5 收敛即压缩** | aligned 球正文移入文档尾部**沉淀区**（`# 沉淀区`，特殊根标题：不可被引用、不参与边），原位留 `- summary:` 摘要 + `[全文](#沉淀区-xxx)` 链接。活动区（顶部）+ 沉淀区（尾部）双区结构。骨架不膨胀：收敛的部分压成磁铁。 |
| **D6 读取方法** | 三级按需下钻：**L0 球名列表**（活动区根标题 + 状态 + aligned 球 summary 一行）→ **L1 单球子标题**（展开一个球）→ **L2 正文片段**。读取指令即选择题：`balls` / `ball <slug>` / `body <slug> [section]`。给的粒度 = f(任务)，不是固定格式。 |
| **D7 运行时** | 流式追加四操作：`add-ball`（新球）/ `absorb`（铁粉入球）/ `advance-status`（状态推进）/ `compress`（aligned 沉淀）。追加校验保证文档始终合法、确定性可解析。**归位判定**（这条发言归哪个球）是 AI 语义策略，不在解析确定性内，但每次追加记录操作类型——可审计。 |
| **D8 与 v1.3** | v1.3.0 Final 冻结不动，不迁移、不回写。v2.0 为独立规范线（spec/v2.0-draft.md）。实现各自声明实现的协议版本。 |
| **D9 议程** | 跨文档引用（沉淀区可落独立文件）、版本化/不可变历史 = v2.x 议程（spec 附录）。 |

## 后果

**正面**：
- L1 骨架免费——任何 CommonMark 解析器的 heading 结构即 L1，协议从
  "提取器"降级为"校验器 + 索引器"；
- 人类审查通道从"读懂 JSON"变成"读 markdown"（显式可见优于隐身）；
- 收敛即压缩使骨架有界（活动区 + 沉淀区）；
- 运行时语义让"AI 说话自动 DAG 化"有协议锚点，与 Helix ADR-0022
  （会话即经历）同构——Mind 复盘直接消费 DAG。

**代价/缺口**：
- 元数据从隐身变可见：状态列表/跨树链接进入渲染（这是有意的转向）；
- 链接指向子标题的语义未定义（协议不拦，但不算边）；
- 归位判定依赖 AI 语义（非纯函数）——靠追加审计与状态机约束兜底；
- Golden Fixtures 需按 v2.0 形态重写（25 → 新语料），14 诊断码需重定。

**风险与对策**：
- 自由文本关系标签 → 语义漂移 → 对策：状态机语境 + 追加审计留痕，
  关系枚举若必要留 v2.1 议程；
- 沉淀区双区结构被误读 → 对策：spec 明确沉淀区不可引用语义。
