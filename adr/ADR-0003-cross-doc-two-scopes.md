# ADR-0003：跨文档作用域——同一协议，两层边界

- **状态**: Accepted
- **日期**: 2026-09-06
- **关联**: ADR-0002（v2 形状/读取/运行时）、v2.0-draft §5.2b（SessionWindow）
- **范围**: lodestone-spec（协议）/ lodestone-md（mddag 实现）

## 1. 背景与问题

会话窗口（ADR-0002 §5.2b）落地后，经历库从"单文档"进入"多文档"。
用户提出跨文档需求：根目录 `.lodestone` 索引文件 + markdown 保持原汁
原味 + 源码关系顺带标注（cargo metadata / rustdoc JSON 投影）。

动手前的核心审查问题：**跨文档能力会不会与单文档协议冲突？
要不要分开协议？还是可配置？**

## 2. 关键洞察：包含关系，不是并列关系

`[label](#slug)` 在 markdown 标准语义中本就是 `[label](path#slug)`
的 path 为空形态（相对当前文档）。同理，单文档 = "库大小为 1 的库"。

因此：
- **不分开协议**——单文档是跨文档的特例，分开协议要解决"两个协议
  之间如何互相引用"，那才是真正的复杂度来源；
- **不搞配置开关**——配置是给真实语义分歧准备的；这里只有作用域
  不同，没有语义分歧。加开关 = 加复杂度 = 违背极致解耦。

## 3. 决策

### D1 语法：一个语法，两种作用域
- 文档内磁力线：`[label](#slug)`（现状不变）；
- 跨文档磁力线：`[label](path#slug)`，path **相对库根**
  （`.lodestone` 所在目录），生成器统一归一化；
- 文档层对跨文档链接只做格式检查（path 非空、语法合法），
  报 `W-CROSS-DOC`（"需库级校验"），不假装能验证目标。

### D2 两级校验，各管一段
| 层 | 管什么 | 校验 |
|---|---|---|
| 文档层（scan/check/ops） | 文档内闭合 | slug 唯一、文档内磁力线目标存在、状态单向、审计 |
| 库层（index/check-index） | 跨文档闭合 | path 存在、目标 slug 存在、跨文档循环检测 |

单文档 check 不撒谎（不假装能验证跨文档目标），库层补全验证——
协议不自相矛盾，是分工。

### D3 操作不新增：边归属 = 所在文档
add-ball / absorb / advance-status / compress / append-sediment /
decay / strip 全部不动。跨文档边归"所在的文档"管：strip 窗口外会话
= 剔它的出边，语义与单文档完全一致。**跨文档不新增操作符**。

### D4 投影双出口：同一核心
- `library <dir> [keep]`：即时查询（每次跑、keep 参数化、stdout）；
- `mddag index <dir> -o .lodestone`：落盘快照（git 可提交、AI 零成本
  读取、库层校验在此完成）；
- 两者复用同一投影/排序/窗口逻辑，输出格式不同——**复用非重复**。

### D5 入边派生，不落盘
`.lodestone` 只投影**出边**（磁力线）。入边（backlinks）是查询时的
反向投影：出边集合 ⇔ 入边集合是双射，显式存双向重复浪费 tokens
（违背极致节能）。物理事实优先：出边是唯一事实，入边是派生视图。
这也保住 markdown 原汁原味——入边不写回源文档。

### D6 循环检测分级
- 文档内循环：文档层（fixture 04 已有，W-CYCLE）；
- 跨文档循环：库层（index 生成时 DFS 检测，A→B→A 报错）。

### D7 零硬编码
- `keep` 是注入参数（示例 12）；
- path 是数据不是字面量，相对库根归一化；
- 索引文件只定义形状（session/created 由消费方写）。

### D8 源码关系标注（用户追问项）
分层投影、零侵入源码注释：
- crate 级：`cargo metadata`（稳定权威依赖图）投影；
- 符号级：rustdoc JSON（nightly）或 tree-sitter 式 repo map——
  Aider repo map 的"token 预算窗口"与 library 窗口同构，可后接；
- 不往源码注释塞 mddag 标记（保住"代码注释全英文"+"markdown
  原汁原味"）。rustdoc intra-doc links 已是 Rust 原生磁力线。

## 4. 备选与拒绝理由

| 备选 | 拒绝理由 |
|---|---|
| 分开两个协议 | 单文档是跨文档特例，分开需解决协议间互引，复杂度倒挂 |
| 配置开关切换模式 | 无真实语义分歧，开关即复杂度；特例关系天然共存 |
| 入边写回源文档 | 污染 markdown（违背原汁原味）；双向存储浪费 tokens |
| .lodestone 取代 library | library 是即时查询（keep 可调），.lodestone 是快照，用途互补 |
| 索引内嵌进文档 frontmatter | 同"入边写回"——污染源；索引外置是 SCIP 工业标准形态 |

## 5. 后果

**正面**：
- 单文档协议一行不改，库层纯增量；
- 索引文件可复核、可提交 git、AI 零成本读取（按需加载的锚点）；
- 两级校验边界清晰，无自相矛盾；
- 入边派生零冗余，极致节能。

**代价/缺口**：
- path 归一化引入"库根"概念，单文档场景需声明库根（= 文档所在目录）；
- 跨文档循环只在 index 时检测，单文档 check 看不见（分工使然）；
- 跨文档链接目标变更后，索引需重新生成才一致（生成物语义，git diff 可见）。

**风险与对策**：
- 索引过期（文档改了没重跑 index）→ 对策：index 生成物语义 + 一致性
  校验（文档 ↔ 索引对齐检查），git 提交前可挂钩子；
- path 形式漂移 → 对策：生成器统一归一化为相对库根，规范唯一形态。

## 6. 一句话总结

> 单文档是跨文档的特例，`#slug` 是 `path#slug` 的特例——
> 同一协议，两层边界：文档层管文档内闭合，库层管跨文档闭合；
> 边归所在文档，入边派生不落盘，索引是快照不是第二种协议。
