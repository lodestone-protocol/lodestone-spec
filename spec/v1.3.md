# Lodestone Protocol (MD-DAG Protocol Specification)
**Version:** 1.3 Final
**Status:** Final
**License:** Apache-2.0
> Lodestone（磁石协议）：为人机对话的知识脱水与收敛而生长。
> 节点如同磁石，从会话沙地吸附有效信息；边作为磁力线登记依赖与分歧；
> draft → converged → aligned 标记观点成型阶段。
> MD-DAG 为本协议广泛使用的别名；语法标识符保持 `mddag`。
**Conformance language:** 本文中的 MUST / MUST NOT / SHOULD / SHOULD NOT / MAY 按 RFC 2119 与 RFC 8174 解释。
**规范性依赖:** CommonMark 0.31.2（块级语义）；Unicode 15.1（Simple Lowercase Mapping）。
---
## 1. 目的与范围
**目的论（原生场景，Lodestone / MD-DAG）**：本协议为**人机对话的知识脱水与收敛**而生长。长会话中，核心观点如磁铁球滚动——从对方沙地吸收铁粉（有效信息），滤去沙砾（歧义与噪声），逐步成型；会话历史随之膨胀，而结论应当保持致密。mddag 为这一收敛过程提供登记簿：**节点**（磁铁球）承载脱水后的结论，**边**（磁力线）登记依赖与分歧，**状态机**（draft → converged → aligned）标记球的成型阶段。协议的第一优先是**机器按需加载**：新会话以骨架重建球阵、按需读取球面，而非重放沙地全史——以此治理会话膨胀。
**消费方角色**：AI agent 是本协议的原生消费方（骨架 + 按需读取是协议的原生用法）；人类的角色以**审查与验收**为主——检视对齐状态、警告列表与分歧域，裁决结论的入列。元数据在源码中的可见性因此为中性考量：可见，即人类的审计通道。
本协议定义在标准 Markdown 文件中嵌入有向无环图（DAG）结构元数据的方法，满足：
1. **机器按需优先**：结构元数据的首要服务对象是机器消费方（AI agent、工具、流水线）；解析输出支持"骨架先行、正文按需"的加载策略，治理长上下文消费的熵预算；
2. **结构零干扰**：元数据不改变文档的结构语义——不产生标题、不进入大纲/目录层级、不构成渲染输出。本协议以 HTML 注释承载元数据，正是对该目标的物理选择：注释的渲染透明性由 CommonMark 规范本身保证，不依赖任何平台的预处理惯例。元数据在源码中的可见性为中性；
3. **机器可确定性解析**：无需语义理解即可提取节点、边与状态；
4. **可移植**：不依赖特定编辑器、平台或渲染器；
5. **确定性优先**：解析结果是文档当前字节的纯函数，不依赖任何外部状态。
**范围限定：本版本仅定义单文档作用域。** 边的引用目标是同一文档内的节点。跨文档引用的语法与语义由后续版本定义，本版本不预留具体语法。
**确定性边界声明：** 本协议承诺的确定性是**解析确定性**——输出是文档当前字节的纯函数。`aligned` 状态不构成内容不可变性的证明：文件字节可能在任意两次解析之间发生变化，本协议无任何机制感知或阻止此变化。内容的跨时间稳定性由协议外机制（如版本控制系统）提供；消费方 MUST NOT 将 `aligned` 视为内容指纹。本版本采取"文件即当前态"模型；版本化与不可变历史为 v2.0 议程（附录 C）。
### 1.4 一致性类
本规范为不同实现角色定义以下一致性类：
| 一致性类 | 角色 | 合规范围 |
|---|---|---|
| **解析器** | 提取节点、边、派生字段，执行校验管线 | MUST 实现 §4–§8 全部 MUST 级要求，并按 §8 契约结构输出 |
| **消费方** | 读取并解释解析输出 | MUST 支持三级加载语义（§9），MUST NOT 将未生效边作为确定性输入 |
| **验证器** | 独立校验文档合规性 | MUST 输出与参考实现一致的错误码与警告码（§11） |
## 2. 术语
| 术语 | 定义 |
|---|---|
| 节点 | 以根级一级标题为边界的一个文档片段 |
| 边 | 节点间显式声明的关系 |
| 元数据 | 以 HTML 注释形式嵌入的结构化数据（节点级与文档级共用同一形态与校验规则） |
| 文档级元数据 | 文件第一个块的 mddag 注释，声明协议版本等文档属性（§3） |
| 声明边集合 | 所有**有效**节点 `edges` 数组中声明的边，保持原文形态（含 derive） |
| 规范化边集合 | 声明边集合经 derive 转置与去重折叠后的集合（§7.2） |
| 全局图 | 由生效边构成的 DAG |
| 生效边 | 双端均为 `aligned` 且通过全部校验的**规范化**边 |
| 无效节点 | 元数据在形态层或 JSON 层校验失败的节点，或因 E-DUP-ID / E-MISSING-ID 被判无效的节点 |
| 上游 | 对齐次序意义上的前提节点（§6） |
| 循环边全集 | 参与至少一个环的全部边（§7.3） |
| 正文 | 节点区间剔除标题行与排除行、再剔除首尾空行后的内容（§8.1） |
| 派生字段 | 由文档字节确定性计算、随节点表输出的字段：`chars`、`body_start`、`body_end`（§8.1） |
## 3. 文件结构
```
┌─ 文档级元数据（HTML 注释，可选）
├─ 节点 0（无标题前言，可选）
├─ 节点 1
├─ 节点 2
└─ ...
```
### 3.1 文档级元数据
- **位置**：文件的第一个块（指 BOM `U+FEFF` 若有之后的第一个 CommonMark 顶层块）；
- **形态**：顶格、单行，以 `<!-- mddag: ` 开始，以 `-->` 结束。注释体约束与节点元数据一致（§5.1：MUST NOT 含 `-->`，SHOULD NOT 含 `--`）；
- **内容**：合法 JSON 根对象。当前唯一已定义字段为 `version`（string）。未知字段 MUST 被忽略；
- **提取规则**：第一个块为顶格单行且精确匹配前缀 `<!-- mddag: ` 的注释时采纳；否则视为普通 HTML 块，本文档无文档级元数据（合法状态，无警告）。
**行为钉死（无实现自由度）：**
| 情形 | 行为 |
|---|---|
| 无文档级元数据 | 按本规范尽力解析 |
| `version` 值非 `"1.3"` | 报 W-VERSION-MISMATCH，**继续按本规范尽力解析** |
| 形态匹配但 JSON 解析失败 / `version` 类型非法 / **JSON 出现重复键** | 报 W-DOC-META，忽略文档级元数据，继续按本规范尽力解析 |
全部失败路径收敛于"警告 + 继续解析"，与缺失路径共用同一行为分支。文档级元数据失败不阻断文档解析。
- 文档级元数据之后若紧跟空行再接标题，节点 1 自该标题开始。文档级注释不属于任何节点。
### 3.2 节点 0
- 节点 0（无标题前言）MUST NOT 携带节点元数据（其无标题行，节点元数据提取的"标题行之后"前置条件天然不满足），MUST NOT 被边引用。
- 节点 0 的内容 MUST NOT 进入节点表、MUST NOT 被边引用、MUST NOT 参与正文计算，但解析器仍须扫描其中以检测 W-META-PLACEMENT。
## 4. 节点
### 4.1 节点边界
- 节点以**根级一级标题**开始，至下一个根级一级标题或文件末尾结束。
- 根级一级标题定义为：**行首零空白缩进**、符合 CommonMark 0.31.2 ATX 标题语法的一级标题（`# `）。此为协议对 CommonMark 的收窄：1–3 空格缩进的标题、以及任何容器块（列表、引用块等）内部的标题，均不构成节点边界，视为正文。收窄不破坏 CommonMark 兼容性。
- 节点边界识别 MUST 基于 CommonMark 0.31.2 块级解析结果：候选标题行 MUST 是文档**顶层块序列**中的块。围栏代码块（任意长度的 ``` / ~~~ 围栏）与缩进代码块的内容 MUST NOT 参与边界识别。
- 实现 MUST NOT 以自定义规则匹配标题行（如仅按行前缀 `#` 判断），因为该做法无法正确处理围栏内内容。
### 4.2 节点标识
- `id` 字符集为 `[a-z0-9_-]`，长度 ≤ 64。
- 未显式声明 `id` 时，由标题文本按以下确定性算法派生 slug：
  1. 按 **Unicode 15.1 Simple Lowercase Mapping**（码位到码位，不执行 full case folding）小写转换；输入 SHOULD 为 NFC 归一化形态；
  2. 非 `[a-z0-9_-]` 字符替换为 `-`；
  3. 连续 `-` 压缩为单个；
  4. 去除首尾 `-`；
  5. 超过 64 字符时截断。
- 派生结果为空字符串时，该节点无可用 id：MUST 报 E-MISSING-ID，节点按无效节点处理。含非 ASCII 字符的标题 SHOULD 显式声明 `id`。解析器 SHOULD 在检测到非 NFC 输入时报告 W-NFC-VIOLATION（非错误，仅提示）。
- **E-DUP-ID 后果定义**：同一文档内有效节点的 id（显式或派生）重复时，报 E-DUP-ID，**同 id 的全部节点按无效节点处理**（完整适用 §5.3 无效节点语义：占位、MUST NOT 被引用、指向该 id 的边报 E-REF-NOT-FOUND）。无效节点不参与重复检测，故本判定不级联。
## 5. 节点元数据
### 5.1 位置与形态
节点元数据注释 MUST 满足：
1. **位置**：节点标题行之后的第一个非空行；
2. **形态**：顶格（零缩进）、单行，以 `<!-- mddag: ` 开始（前缀中两个空格位置精确匹配，符合 CommonMark 0.31.2 §6.1 对 HTML 块起始类型的定义），以 `-->` 结束；
3. **注释体**：两个定界符之间的子串，不含换行。
**提取规则**：
- 候选行若顶格以 `<!-- mddag: ` 开始且该行以 `-->` 结尾：采纳，注释体为中间子串；
- 候选行顶格以 `<!-- mddag: ` 开始但不以 `-->` 结尾（跨行或未闭合）：E-META-SYNTAX，节点按无效节点处理；
- 候选行出现**近似前缀变体**（如 `<!--mddag:` 缺首空格、`<!-- mddag:` 缺尾空格）或不符合上述形态（缩进、位置靠后等）：节点无元数据，按字段缺省值处理，解析器报 W-META-PLACEMENT。
**注释体内容约束**：
- 注释体 MUST NOT 包含 `-->` 序列。检测到体内残留 `-->` 时 MUST 报 E-META-SYNTAX。
- 注释体 SHOULD NOT 包含 `--` 序列。检测行为由实现自行决定。
- 节点内后续位置出现的 mddag 注释 MUST 被忽略，并 MAY 报告 W-REDUNDANT-META。
### 5.2 字段定义
| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 否（SHOULD 显式声明） | 节点标识，见 §4.2 |
| `status` | enum | 否 | `draft` \| `converged` \| `aligned`，缺省视为 `draft` |
| `edges` | array | 否 | 出边列表，见 §7 |
| `tags` | array | 否 | 自由标签；可用于标记对齐层级（如 `ai-aligned`, `human-reviewed`）等元数据属性，由消费方在投影层解读 |
| `updated` | string | 否 | RFC 3339 时间戳。信息性字段，MUST NOT 参与任何协议层计算 |
未知字段 MUST 被忽略。
**JSON 语义约束**：
- 注释体 MUST 为合法 JSON 根对象。JSON 根对象中出现**重复键**时，解析器 MUST 报 E-META-SYNTAX，节点按无效处理。此举旨在消除不同 JSON 解析器对重复键处理不一致带来的确定性风险。
### 5.3 容错分层
校验分三层，失败后果逐层递减：
| 层 | 检查内容 | 失败后果 |
|---|---|---|
| 形态层 | §5.1 位置与形态约束 | E-META-SYNTAX，节点无效 |
| JSON 层 | 注释体为合法 JSON 根对象（含重复键检测） | E-META-SYNTAX，节点无效 |
| 字段层 | 字段值合法性 | E-META-FIELD，部分降级 |
字段层降级规则：
- `status` 值非法：回退为 `draft`；
- `edges` 中某条边缺 `to` 或 `relation`、或值非法：剔除该边，其余边保留；
- `id` 不符合 §4.2 字符集或长度：视为无 id，走 E-MISSING-ID 路径；
- `tags` 非字符串数组：忽略该字段。
**无效节点语义**：无效节点在输出中保留为占位（含标题），标注为 invalid；MUST NOT 参与图结构计算；MUST NOT 被其他边引用——指向无效节点的边报 E-REF-NOT-FOUND；不参与 E-DUP-ID 检测；骨架视图中 SHOULD 可见并标注。
## 6. 节点状态机
```
draft ──> converged ──> aligned
```
| 状态 | 语义 |
|---|---|
| `draft` | 内容未定，可随时修改 |
| `converged` | 作者断言内容已稳定 |
| `aligned` | 作者断言：内容已稳定，**且已与其全部上游完成对齐**。此状态为作者的社会契约断言，非物理不可变证明。未生效边在规范化边集合中保留，仅不进入全局图。 |
**上游的唯一形式化定义**：给定节点 X，X 的每条**规范化 depend 出边** `X --depend--> Y` 的目标 Y 为 X 的上游。`support` 与 `refute` 为评价性关系，不定义上下游，不参与对齐次序。
约束：
1. 状态转换仅允许单向进行。回退属于显式操作，允许执行；其对下游的影响超出本规范范围，工具 MAY 提示。
2. 状态由作者或工具显式声明；解析器 MUST NOT 推断或修改状态。
3. 工具 SHOULD 校验：声明 `aligned` 的节点若存在非 `aligned` 的上游，报告 W-UPSTREAM-PENDING。
4. 延迟绑定规则：一条规范化边仅当其**源节点与目标节点均为 `aligned`** 且通过全部校验时，才进入全局图。局部结论在收敛前不污染全局结构。
*(数学化表述见附录 A)*
## 7. 边
### 7.1 声明方式
边仅在元数据 `edges` 数组中显式声明，单行书写：
```json
"edges": [ { "to": "exp-01", "relation": "depend" } ]
```
正文链接 `[文本](目标)` 仅为人类可读提示，MUST NOT 作为机器解析依据。
### 7.2 关系类型与规范化
| relation | 书写语义（作者视角） | 规范化处理 | 参与对齐次序 |
|---|---|---|---|
| `depend` | 源节点的成立依赖目标节点 | 不变 | 是 |
| `derive` | 目标节点由源节点推导而来 | **转置为 depend**：`S --derive--> T` 规范化为 `T --depend--> S` | 是（转置后） |
| `support` | 源节点为目标节点提供支撑 | 不变 | 否 |
| `refute` | 源节点为目标节点的反证 | 不变 | 否 |
**derive 的定位**：depend 的**转置书写视角**，为作者便利保留的语法糖。**持久化格式均合法；解析输出一律折叠为 depend 方向。**
互斥关系必须通过 `refute` 显式声明，禁止依赖隐式推断。
**规范化管线**：
1. 每条 derive 边转置为 depend；
2. 转置后，凡 (源， 目标， relation) 三元组完全相同的多条边，折叠为一条，每多出一条报 **W-REDUNDANT-EDGE**；
3. 环检测、引用校验、生效判定均在**规范化边集合**上执行。
### 7.3 生效与环检测
- **声明边集合**：全部有效节点声明的边。软环检测 SHOULD 在**规范化边集合**上执行；发现环时报告 W-CYCLE-DECLARED。
- **全局图（生效边）**：仅含双端均为 `aligned` 且通过全部校验的规范化边。
- **环检测与循环边全集**：解析器 MUST 在全局图上执行环检测；存在环时报 E-CYCLE。失效集合定义为**循环边全集**。循环边全集内全部边不生效，其余子图正常输出。
## 8. 解析器义务与输出契约
符合本协议的解析器 MUST 按以下管线顺序执行：
1. 基于 CommonMark 0.31.2 块级解析切分节点；
2. 提取文档级元数据（§3.1），按钉死行为执行版本协商；
3. 按 §5.1 提取节点元数据，执行 §5.3 三层校验，划分有效/无效节点；
4. 执行 E-DUP-ID 判定；
5. 计算全部节点的派生字段（§8.1）；
6. 自有效节点提取声明边集合，执行 §7.2 规范化；
7. 在规范化边集合上校验引用目标可解析且非无效节点（E-REF-NOT-FOUND）；
8. SHOULD 执行声明层软环检测与 aligned 上游校验；
9. 判定生效边（双端 aligned），在全局图上执行环检测（E-CYCLE，循环边全集失效）；
10. 输出。
### 8.1 派生字段（节点表契约）
节点表仅含带标题行的节点。每个节点条目结构：
```json
{
  "id": "string | null",
  "status": "draft | converged | aligned",
  "valid": "boolean",
  "tags": "array",
  "chars": "integer >= 0",
  "body_start": "integer | null",
  "body_end": "integer | null"
}
```
实现 MAY 在契约字段之后携带附加字段（如 `title`，用于 §5.3 无效节点占位），消费方 MUST 忽略未识别的附加字段。
**正文区间的计算规则（对有效与无效节点统一适用）：**
1. 节点区间 = 标题行起，至下一节点标题行前一行（或文件末行）止；
2. **排除行**：若标题行之后的第一个非空行是单行完整形态的 mddag 注释，该行为排除行；否则无排除行。未闭合、跨行或近似前缀变体的注释**不构成排除行**；
3. 候选正文 = 节点区间剔除标题行与排除行（若有）；
4. 正文区间 = 候选正文剔除**首尾**空行后的区间；内部空行保留。剔除后为空时，`chars` 为 0，区间字段为 null；
5. **物理行号**：`body_start` / `body_end` 指原始文件中的物理行号（1-based，按换行符序列计数，CRLF 视为一行结束）。
6. **chars** = 正文文本的 Unicode 码点数。正文文本 = 正文区间内各行去除行尾换行序列（LF、CRLF 或 CR）后，按原序以 U+000A 连接所得的字符串。
> 注：行内尾随空格计入 `chars`。作者工具 MAY 在保存时自动剔除尾随空格以消除此类视觉差异。
### 8.2 规范化边集合契约
规范化边集合包含全部有效节点声明并经 §7.2 规范化后的边，**无论其是否生效**。每条边条目结构：
```json
{
  "from": "string",
  "to": "string",
  "relation": "depend | support | refute",
  "effective": "boolean",
  "failure": "string | null"
}
```
- `from` / `to`：规范化后的源节点与目标节点 id。
- `relation`：规范化后的关系（derive 已转置为 depend）。
- `effective`：是否生效（进入全局图）。
- `failure`：若 `effective` 为 false，标注失效原因（如 `"E-REF-NOT-FOUND"`, `"E-CYCLE"`, `"W-UPSTREAM-PENDING"`）；若 `effective` 为 true，则为 `null`。单条边在解析管线中只会命中一种主要失效原因。
### 8.3 错误与警告列表契约
解析器输出的错误与警告列表，每条条目结构：
```json
{
  "code": "string (如 E-CYCLE, W-VERSION-MISMATCH)",
  "level": "error | warning",
  "node_id": "string | null",
  "edge": "string | null (如 'concl-01 -> exp-01')",
  "message": "string (人类可读描述)"
}
```
### 8.4 全局图契约
全局图表示为生效边的集合：
```json
{
  "nodes": ["id1", "id2"],
  "edges": [
    { "from": "id1", "to": "id2", "relation": "depend" }
  ]
}
```
## 9. 消费方行为（三级加载）
本协议的原生读取模式是三级加载。加载级别的选择权在消费方——按任务需要分配熵预算：
| 级 | 内容 | 相对成本 | 典型任务 |
|---|---|---|---|
| **L1 骨架** | 节点表 + 规范化边集合 + 错误/警告列表 | 极低 | 重建全局认知、规划读取、对齐审查 |
| **L2 定点正文** | 依 `body_start` / `body_end` 读取选中节点的正文 | 中 | 回答具体问题、追溯依赖链 |
| **L3 全文** | 文档全部字节 | 高 | 查全率任务：审查、迁移、安全审计；或用户明示需要完整细节 |
**遗漏的责任分工**：L1/L2 遗漏是策略性取舍；L3 查全率是消费方对确定性任务的义务；降级路径（L1 → L2 → L3）永远可用。作者侧路标（`tags`、`status` 与节点标题）是发现细节的第一锚点。
**AI 消费方最小合规子集**：AI agent 的最小合规子集为 L1 + L2，L3 仅为查全率任务保留。此加载策略与 Skill Graph 架构中的渐进式披露同构，均基于清晰的边界标识实现分段检索。
约束：
- 非 `aligned` 节点的正文与未生效边仅作为参考上下文，MUST NOT 作为确定性结论的输入。
- 消费方 MUST NOT 假定两次读取之间 `aligned` 节点内容不变；需要跨时间稳定性时，应使用外部版本控制机制钉扎字节。
## 10. 完整示例
外层使用四反引号围栏，以容纳内部的三反引号代码块：
````markdown
<!-- mddag: {"version":"1.3"} -->
# 流体实验记录
<!-- mddag: {"id":"exp-01","status":"aligned","tags":["experiment"]} -->
实验数据与原始观测记录。
# 采集参数快照
<!-- mddag: {"id":"exp-01-config","status":"aligned"} -->
采集环境如下：
```text
# 通道配置（位于围栏内，不构成节点边界）
channel-1: 压力传感器
channel-2: 流速计
```
# 实验结论
<!-- mddag: {"id":"concl-01","status":"converged","edges":[{"to":"exp-01","relation":"depend"},{"to":"exp-01-config","relation":"depend"}]} -->
基于 [实验记录](#流体实验记录) 的推导。
# 反例观察
<!-- mddag: {"id":"counter-01","status":"draft","edges":[{"to":"concl-01","relation":"refute"}]} -->
一次与结论冲突的观测。
# 后续计划
<!-- mddag: {"id":"plan-01","status":"draft","edges":[{"to":"old-note","relation":"depend"}]} -->
待定。
````
解析输出（节点表数值经独立参考实现计算验证）：
| id | status | valid | chars | body 区间 |
|---|---|---|---|---|
| exp-01 | aligned | true | 12 | 5–5 |
| exp-01-config | aligned | true | 74 | 9–15 |
| concl-01 | converged | true | 23 | 19–19 |
| counter-01 | draft | true | 11 | 23–23 |
| plan-01 | draft | true | 3 | 27–27 |
规范化边集合包含上述全部边（含 `plan-01` 指向 `old-note` 的失效边）。全局图为空（因 `concl-01` 未 `aligned`）。
## 11. 错误码与警告码汇总
| 代码 | 级别 | 含义 | 确定性后果 |
|---|---|---|---|
| E-MISSING-ID | 错误 | 节点无可用 id | 节点无效 |
| E-META-SYNTAX | 错误 | 元数据形态非法 / JSON 解析失败 / **重复键** | 节点无效 |
| E-META-FIELD | 错误 | 字段值非法 | 节点有效，字段降级 |
| E-DUP-ID | 错误 | 有效节点 id 重复 | 同 id 全部节点无效 |
| E-REF-NOT-FOUND | 错误 | 边引用目标不存在或为无效节点 | 该边不生效 |
| E-CYCLE | 错误 | 全局图存在环 | 循环边全集失效 |
| W-VERSION-MISMATCH | 警告 | 文档级 `version` 非 `"1.3"` | 继续解析 |
| W-DOC-META | 警告 | 文档级元数据 JSON 不合法 / **重复键** | 忽略之，继续解析 |
| W-CYCLE-DECLARED | 警告 | 规范化声明边集合存在环 | 无结构影响 |
| W-REDUNDANT-EDGE | 警告 | 规范化后重复 | 折叠为一条边 |
| W-META-PLACEMENT | 警告 | 疑似元数据出现在非法位置/形态 | 节点无元数据 |
| W-REDUNDANT-META | 警告 | 节点内存在被忽略的后续 mddag 注释 | 忽略该注释 |
| W-UPSTREAM-PENDING | 警告 | aligned 节点存在非 aligned 上游 | 无结构影响 |
| W-NFC-VIOLATION | 警告 | 标题文本未采用 NFC 归一化形态 | 无结构影响 |
## 附录 A：视图投影与数学参考（非规范性）
**视图投影**：边状态标签是消费方可从（status、规范化边集合、错误列表）确定性计算的**投影**。协议仅规范事实，不规范呈现。
| 标签 | 条件 | 渲染建议 |
|---|---|---|
| coherent | 生效边（双端 aligned） | 绿 |
| pending | 恰一端 aligned 的规范化边 | 黄 |
| nascent | 双端均非 aligned 的规范化边 | 灰 |
| redundant | 携带 W-REDUNDANT-EDGE 的折叠边 | 灰（带提示） |
| dangling | E-REF-NOT-FOUND 的边 | 黑 |
| cyclic | 处于循环边全集的边 | 虚线 |
投影的第一消费方是**机器读取策略**。人类界面 MAY 将 `chars` 显示为约数（如 `8.5k`）。消费方亦可通过解读 `tags`（如 `ai-aligned` vs `human-reviewed`）在投影中区分对齐层级。
**数学参考**：§6 的状态机构成全序链，可视为 join-semilattice ⟨{draft, converged, aligned}, max⟩。状态转换为沿此链的单调递增操作。CRDT 半格理论为其提供了分布式状态收敛的理论背书。
**第三极定位**：MD-DAG 的元数据位置选择（§5.1 标题后首非空行）是对个人知识管理领域长期争论的回应。YAML frontmatter 适合文件级全局元数据，Dataview inline 字段适合段落级局部数据，而 HTML 注释节点级元数据填补了两者之间的空白——与文档结构天然对齐，同时保持渲染透明性。
Obsidian 等环境的替代注释写法（如 `%%` 包裹）属于插件层语法糖，不属于本协议；插件 MUST 在持久化时序列化为 §5.1 规范形态。
**实现提示（性能优化）**：消费方若仅需 L1 骨架，MAY 采用启发式快速扫描（识别顶格 `# ` 与顶格 `<!-- mddag: `）作为优化路径，但 MUST 在需要精确 `chars` 或处理含围栏代码块的文档时回退到完整 CommonMark 0.31.2 解析。

## 附录 C：v2.0 议程
