# Lodestone Protocol v2.0-draft（MD-DAG 2）
**Version:** 2.0-draft
**Status:** Draft（评审中，未冻结）
**License:** Apache-2.0
**Supersedes:** v1.3.0（冻结不迁移，见 §7）
> Lodestone（磁石协议）：知识的形状 + 读取的方法 + 运行的时。
> 人机交流如数颗磁铁球（主线）在沙地（冗余与歧义）中滚动——球吸附铁粉
> （对齐的有用信息），筛去沙子（无用冗余），球体越来越稳固清晰。
> v2.0 的载体是 markdown 本身：**大纲即骨架、链接即磁力线、正文即铁粉、
> 状态是列表；收敛即压缩、读取按需下钻、追加流式归位。**
> 语法标识符沿用 `mddag`。
**Conformance language:** MUST / MUST NOT / SHOULD / SHOULD NOT / MAY 按 RFC 2119 与 RFC 8174 解释。
**规范性依赖:** CommonMark 0.31.2（块级语义）；Unicode 15.1（Simple Lowercase Mapping）。

---
## 1. 目的与范围
**目的论**：长会话中核心观点如磁铁球滚动——从对方沙地吸收铁粉，滤去沙砾，
逐步成型。会话历史随之膨胀，而结论应当保持致密。v2.0 为这一收敛过程提供
三件套：
1. **形状（Shape）**：markdown 原生结构表达 DAG——零 HTML 注释、零 JSON；
2. **读取方法（Read）**：L0/L1/L2 按需下钻 + 收敛即压缩，治理骨架膨胀；
3. **运行时（Runtime）**：流式追加四操作，AI 说话自动 DAG 化，按需获取。

消费方角色不变：AI agent 是原生消费方（L0/L1 骨架 + L2 按需正文）；
人类以审查与验收为主（状态列表与链接即审计通道）。元数据**可见**且原生，
这是与 v1.3（隐身注释）的决定性差异。

**范围限定**：本版本仅定义单文档作用域。跨文档引用（沉淀区可落独立文件）
与版本化/不可变历史为 v2.x 议程（附录 B）。

**确定性声明**：解析输出是文档当前字节的纯函数，不依赖任何外部状态
（与 v1.3 承诺一致）。归位判定（AI 语义）不在解析确定性内，但每次追加
记录操作类型——追加可审计（§5.4）。

## 2. 术语
| 术语 | 定义 |
|---|---|
| 球（ball） | 以根级一级标题为边界的一个文档片段（v1.3 的"节点"更名——磁铁球本体） |
| 铁粉 | 球内正文段落——吸附的对齐信息 |
| 磁力线（边） | 球正文中指向**其他球**的 markdown 链接 |
| 沉淀区 | 文档尾部特殊球（`# 沉淀区`），收敛正文的归档处，不可被引用 |
| 活动区 | 沉淀区以外的全部文档内容 |
| 状态 | 球正文顶部 `- status:` 列表项：draft / converged / aligned |
| 摘要 | aligned 球原位保留的 `- summary:` 列表项（收敛即压缩） |
| 骨架 | 文档的 heading 树（L0/L1 的原料），任何 CommonMark 解析器可得 |
| 生效边 | 双端均为 aligned 且目标存在的磁力线（与 v1.3 语义一致） |
| 读取指令 | L0/L1/L2 下钻的指令语法（§4.4） |
| 追加操作 | 运行时五类变更：add-ball / absorb / advance-status / compress / append-sediment（§5.1） |
| 派生字段 | 由文档字节确定性计算的字段：`slug`、`chars`、`body_start`、`body_end` |

## 3. 形状（Shape）
### 3.1 文档结构
```
┌─ 活动区
│   ├─ 球 A（根级 # 标题）
│   │   ├─ 元数据列表（- status: ... [- summary: ...]）
│   │   ├─ 正文（铁粉：段落 + 磁力线链接）
│   │   └─ 子标题层级（球内树）
│   ├─ 球 B
│   └─ ...
└─ 沉淀区（# 沉淀区，最后一个球）
    └─ 收敛正文（aligned 球的完整正文归档，子标题树折叠为二级标题）
```
- 根级一级标题定义沿用 v1.3 §4.1（行首零缩进、CommonMark 顶层块、
  围栏内不参与边界识别）。
- `# 沉淀区` 为保留标题：MUST NOT 被磁力线引用；其内子标题不参与
  球级边；引用沉淀区的链接为普通 markdown 链接。

### 3.2 球标识（slug）
- 球的 `slug` 由标题文本按 v1.3 §4.2 算法确定性派生（Unicode 15.1
  Simple Lowercase Mapping → 非 `[a-z0-9_-]` 替换为 `-` → 压缩 → 去首尾
  → 截断 64）。派生为空 → E-MISSING-ID，球无效。
- 同文档内 slug 重复 → E-DUP-ID，同 slug 全部球无效（语义同 v1.3 §4.2）。
- 无显式 id 声明——纯派生（v1.3 的显式 id 机制废弃）。

### 3.3 状态列表
- 球标题行之后的**第一个非空块** MUST 是元数据列表（否则球无状态，
  按 draft 处理，报 W-STATUS-MISSING）。
- 元数据列表为 markdown 无序列表，项形态 `- key: value`：
  - `status`：`draft` | `converged` | `aligned`。缺失视为 draft。
  - `summary`：仅 aligned 球 MAY 携带（收敛摘要，见 §3.5）。
  - 未知键 MUST 被忽略。
- 状态机：draft → converged → aligned（单向推进，不可回退）。
  非法转移报 E-STATUS-TRANSITION（仅追加操作触发的转移需校验，§5.2）。

### 3.4 磁力线（边）
- 球正文中的链接 `[标签](#target-slug)`，若 target-slug 解析为**其他球**
  的 slug，即为磁力线。
- 磁力线方向：从当前球指向目标球。链接文本 = 关系标签（自由文本，
  MUST NOT 为空；如 `依赖`、`反驳`、`支撑`——语义由状态机语境解读，
  协议不设枚举）。
- 目标 slug 在文档中不存在 → 报 W-REF-NOT-FOUND（非错误，普通链接处理）。
- 目标为沉淀区/子标题 → 普通 markdown 链接，不算磁力线。
- 指向自身 → 报 W-SELF-REF。
- **生效边**：双端均为 aligned 的磁力线。全局图（仅生效边）MUST 无环
  （环检测算法沿用 v1.3 §7.3；检出环报 E-CYCLE）。

### 3.5 收敛即压缩（aligned 球）
aligned 球正文 MUST 被压缩：
1. 原完整正文移入沉淀区（`## <slug>-full` 子标题下，字节保留）；
2. 原位正文替换为元数据列表追加 `- summary: <收敛摘要>` +
   一个指向沉淀区的链接 `[全文](#<slug>-full)`；
3. 球内子标题树随正文整体移入沉淀区（折叠进 `## <slug>-full`）。
- 压缩后该球在 L0 只占一行（`# slug` + status + summary）。
- 压缩是追加操作 `compress` 的产物（§5.1），解析器对已压缩球
  MUST NOT 把沉淀区内容重复计入其 body。

## 4. 读取方法（Read）
### 4.1 L0——球名列表（全局感知）
默认读取输出：活动区每个球的 `# 标题`（slug）+ 状态；aligned 球附加
summary 一行。沉淀区不出现（除非显式请求）。典型体积：每球一行。
**实现约束**：L0 可由任意 CommonMark 解析器的 heading 结构 + 元数据列表
直接得出——不需要专用提取器（v2.0 与 v1.3 的关键差异）。

### 4.2 L1——单球子标题（定位）
指定一个 slug：输出该球（含摘要）的子标题树（heading 层级 + 状态）。
正文不输出（除 summary）。

### 4.3 L2——正文片段（回答问题）
指定 slug + 可选子标题锚点：输出对应正文。体积 = 目标片段本身。

### 4.4 读取指令（指令即选择题）
协议定义最小指令集（实现 MAY 扩展）：
| 指令 | 语义 | 示例 |
|---|---|---|
| `balls` | L0 球名列表 | `balls` |
| `ball <slug>` | L1 单球展开 | `ball exp-01` |
| `body <slug> [anchor]` | L2 正文 | `body exp-01 采集参数` |
| `sediment` | 沉淀区索引（收敛正文的标题列表） | `sediment` |
- 指令是读取协议的契约面（机器/人对齐"给什么"）；实现 MUST 支持
  balls / ball / body，SHOULD 支持 sediment。

## 5. 运行时（Runtime）
### 5.1 追加操作
文档变更通过五类追加操作表达（每次操作 = 一行审计记录，§5.4）：
| 操作 | 语义 | 合法性约束（MUST） |
|---|---|---|
| `add-ball` | 新建球（根标题 + 状态列表 + 初始正文） | slug 不重复；状态合法 |
| `absorb` | 铁粉写入已有球（追加正文/子标题） | 目标球存在且非 aligned（aligned 球只可进沉淀区） |
| `advance-status` | 状态推进（draft→converged→aligned） | 单向；目标球存在 |
| `compress` | aligned 球正文移入沉淀区 + 原位留 summary/全文链接 | 仅 aligned 球；沉淀区目标 slug 不重复 |
| `append-sediment` | 向沉淀区追加/修订收敛正文 | 仅沉淀区内；不改变球级结构 |
- 追加操作 MUST 保持文档解析合法：任何一步之后，§3 的全部形态约束
  依然满足，解析输出仍为字节纯函数。

### 5.2 归位判定（AI 策略，可审计）
"这条发言归哪个球 / 新建球 / 推进状态"的判定是 **AI 语义策略**——
不在解析确定性内，协议不规定算法。协议只约束：
- 判定结果 MUST 落为 §5.1 的追加操作之一（否则该发言不改变文档）；
- 每次追加 MUST 附带审计记录（§5.4），人类可复核"谁、何时、把什么
  归到了哪"。

### 5.3 确定性与审计
- 解析确定性：输出 = 文档字节纯函数（§1 承诺）。
- 追加审计：文档头部（或独立审计段，实现选择）MUST 记录追加操作日志
  （操作类型 + slug + 时间戳 + 来源），格式为元数据列表或代码块。
  审计记录不参与 L0/L1/L2 输出。

## 6. 一致性类
| 一致性类 | 角色 | 合规范围 |
|---|---|---|
| **解析器** | 输出 L0/L1/L2 + 派生字段，执行形态校验 | MUST 实现 §3–§4 全部 MUST 级要求 |
| **摄取器** | 执行 §5.1 追加操作 + 审计 | MUST 满足 §5 合法性约束，MUST NOT 产生非法文档 |
| **消费方** | 按指令读取 | MUST 支持 §4.4 最小指令集，MUST NOT 将未生效边作为确定性输入 |

## 7. 与 v1.3 的关系
- v1.3.0 Final **冻结**：语法、fixtures、诊断码不再回写、不迁移。
- v2.0 是独立规范线。实现 MUST 声明实现的协议版本
  （"Implements Lodestone Protocol v2.0-draft"）。
- 语义延续：slug 算法、E-DUP-ID/E-MISSING-ID、生效边、环检测、
  三级读取思想——从 v1.3 继承；载体与读取方法重做。

## 8. 诊断码（草案，v2.0-draft）
保留继承：`E-MISSING-ID`、`E-DUP-ID`、`E-CYCLE`、`W-REF-NOT-FOUND`。
新增/更名：
| 码 | 级别 | 语义 |
|---|---|---|
| `W-STATUS-MISSING` | warning | 球无状态列表，按 draft 处理 |
| `E-STATUS-TRANSITION` | error | 状态机非法回退/跳级（追加校验） |
| `W-SELF-REF` | warning | 球引用自身 |
| `E-SEDIMENT-REF` | error | 磁力线指向沉淀区 |
| `E-ABSORB-ALIGNED` | error | absorb 写入 aligned 球（应走沉淀区） |
| `W-AUDIT-MISSING` | warning | 追加无审计记录 |

## 附录 A：文档示例（v2.0 形态）
```markdown
# 流体实验记录
- status: converged
实验数据与原始观测记录。

# 采集参数快照
- status: aligned
- summary: 采集环境为双通道压力/流速，围栏配置见全文。
[全文](#采集参数快照-full)
正文首段……（本例已压缩，原文在沉淀区）

# 实验结论
- status: aligned
- summary: 基于记录与参数快照，结论成立；反例观察未推翻。
[全文](#实验结论-full)
[依赖](#流体实验记录) [依赖](#采集参数快照)

# 反例观察
- status: draft
一次与结论冲突的观测。[反驳](#实验结论)

# 沉淀区
## 采集参数快照-full
（原始正文迁移至此）
## 实验结论-full
（原始正文迁移至此）
```

## 附录 B：议程（v2.x，不阻塞 v2.0）
- 跨文档引用：沉淀区可落独立文件，`[label](path#slug)` 进磁力线语义；
- 版本化/不可变历史：aligned 即内容指纹（v1.3 明确拒绝，v2 重议）；
- 关系枚举：若自由文本标签漂移失控，定义受限枚举（`depend/refute/…`）；
- 指令协议化：读取指令若跨实现复用，定义 wire 格式。
